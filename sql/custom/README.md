# SQL RPS и NobleNext

Автоматические изменения каждой базы находятся в `auth`, `characters`, `world` и `hotfixes`. Штатный апдейтер читает соответствующие `updates_include` и сортирует файлы по имени. Ручные операции находятся в [manual/rps_combat](manual/rps_combat/README.md). Этот каталог расположен вне четырёх автоматических путей. Добавлять весь `sql/custom` в `updates_include` нельзя, поскольку здесь также лежат межбазовые и ручные SQL.

## Установка RPS Combat

Начните со схем и обязательных SQL RoleplayCore той версии, из которой собрано ядро. Нужны таблицы HOTFIXES `spell` и `spell_locale`, а также столбец WORLD `npc_vendor.OverrideGoldCost`. Перед применением выберите нужную базу, сделайте резервную копию и остановите процессы записи. SQL-клиент должен останавливаться при первой ошибке.

На чистой схеме порядок RPS-файлов следующий.

| База | Порядок |
|---|---|
| HOTFIXES | `2026_10_26_00_rps_dice_spells.sql` → `2026_10_27_00_rps_action_spells.sql` → `2026_10_27_01_rps_spells_skill_line.sql` → `2026_10_27_03_rps_spells_skill_line_classmask.sql` → `2026_10_30_00_rps_combat_hotfixes.sql` |
| WORLD | `2026_10_30_00_rps_combat_world.sql` → `2026_10_30_01_rps_enable_dice_spells.sql` |
| CHARACTERS | `2026_10_27_01_rps_character_creation.sql` → `2026_10_27_02_rps_race_preset.sql` → `2026_10_30_00_rps_combat_characters.sql` |

Этот порядок совпадает с сортировкой штатного апдейтера внутри каждой базы. Связанные предметные пакеты для ручного развёртывания выполняйте в порядке HOTFIXES, WORLD, CHARACTERS. Для замены стартовой экипировки новым персонажам отдельно выберите ручной пакет WORLD и согласуйте настройку `RPS.StarterOutfit.ReplaceLoadout`. Рассылки экипировки существующим персонажам выбираются отдельно.

## Обновление существующей базы

Проверьте как `updates`, так и данные. При ручном импорте запись файла в `updates` могла отсутствовать. HOTFIXES распознаёт установленные записи кубов, действий и SkillLine, включая дополнительные уведомления актуальных иконок. Маска `16383` сохраняется, известная прежняя маска `0` исправляется с новыми уведомлениями. Неполные и конфликтующие наборы требуют сверки и сохраняются при отказе.

WORLD сохраняет уже созданного собственного торговца и его положение. Определения характеристик, экипировки и RP-чар дополняются без замены действующих значений. CHARACTERS сохраняет существующие профили и состояния создания. Отдельные секции пакетов используют собственные транзакции. Полный файл содержит DDL и несколько транзакций, поэтому после ошибки проверьте завершённые секции перед повтором.

В локальном окружении `make db-update` сначала выполняет `make db-check`. Проверка показывает точные пути, выявляет повторяющиеся имена и проверяет опасные условия для штатных Housing SQL. Перед запуском сверяются подключения с рабочим конфигом, дополнительными `.conf` и переменными `TC_*`. Ручные SQL в автоматической очереди останавливают обновление. Этот запуск сохраняет журнал вынесенных файлов и пропускает зарегистрированные имена. Новые исправления ранее выполненных SQL оформляйте отдельными миграциями.

При поставке переносите удаления вместе с добавлениями. Старые автоматические файлы повышения уровня и кривой опыта, прежнее имя WORLD-включения кубов и две копии Housing из `sql/custom/world/Housing` должны исчезнуть из развёрнутого дерева. Содержимое `sql/updates` поставляется из принятой версии upstream.
